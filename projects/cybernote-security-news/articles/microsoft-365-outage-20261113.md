# Microsoft 365で大規模障害、OutlookやTeamsに接続できず｜原因と復旧状況、取るべき対応【2026年11月13日】

2026年11月13日未明（日本時間）、[Microsoft](https://www.microsoft.com/ja-jp)のMicrosoft 365で大規模な障害が起き、Outlookのメールに接続できない状態が世界各地に広がりました。
影響はメールにとどまらず、TeamsやSharePoint Online、Microsoft 365 Copilotなど、業務の中心となるサービスにも及んでいます。

Microsoftは、多数のサーバーが正常性チェックに失敗して使えなくなり、残った設備に負荷が集中したと説明しています。
午後8時時点でメールの接続や遅延メールの処理は改善していますが、全面復旧は未発表です。本記事では経緯と原因、利用者と管理者の対応をまとめます。

## Microsoft 365障害の概要

今回のMicrosoft 365障害は、メールの仕組みであるExchange Onlineから始まり、複数のサービスへ広がりました。
まずは発生時刻や影響範囲、障害番号など、公式発表で確認できる基本情報を整理します。

### 障害の基本情報

Microsoftは障害を2つの番号で管理しています。
1つはExchange Onlineのメールボックスに接続できない問題を指すEX1550543、もう1つはMicrosoft 365全体の接続障害を指すMO1550821です。
管理者は、この2つの番号を手がかりにして管理センターで最新情報を追えます。

| 項目 | 内容 |
|---|---|
| 発生日時 | 2026年11月13日未明（日本時間）、米国時間では11月12日の昼過ぎ |
| 公表 | 日本時間13日午前2時54分、公式Xで調査開始を発表 |
| 影響地域 | 当初は米州。その後「すべての地域で影響の可能性」と説明を改めた |
| 障害番号 | EX1550543（Exchange Online）、MO1550821（Microsoft 365全体） |
| 原因 | 多数のサーバーが自動の正常性チェックに失敗し、残りの設備に負荷が集中 |
| サイバー攻撃 | Microsoftは攻撃を示す兆候はないと説明 |

表のとおり、影響地域は途中で米州から全地域へと広げられており、日本国内の利用者も対象に含まれます。
本記事の作成時点（11月13日午前）で、Microsoftは全面的な復旧の時刻や根本原因をまだ発表していません。
復旧は利用者ごとに段階的に進むため、つながる人とつながらない人が混在する状況が続きました。

### 影響を受けたサービス

Microsoft 365全体の障害通知MO1550821では、影響の可能性があるサービスが時間の経過とともに、順次追加されました。
メールやチャットだけでなく、ファイル共有、AIアシスタント、セキュリティ監視や情報管理の画面まで含まれており、影響範囲は業務全体に及んでいます。
主な対象は次のとおりです。

- Exchange Online（Outlookのメール・予定表）
- Microsoft Teams
- SharePoint Online
- Microsoft 365 Copilot
- Microsoft Defender XDR
- Microsoft Planner／Microsoft To Do
- Microsoft Purview

このうちDefender XDRとPurviewは、セキュリティ担当者が脅威の監視や情報管理に使う画面です。
障害中は、メールが使えないだけでなく、社内の監視や調査の作業も止まりやすくなります。
セキュリティ部門は、監視が止まっていた時間帯を記録しておき、復旧後にアラートの見落としがないか確認しましょう。

## 障害の経緯

今回の障害は、北米でのTeamsの不具合に続いて起きたメールの接続障害が、わずか数時間で世界規模に広がったものです。
ここでは、公式発表の時系列と、利用者側で実際に見られた症状を順を追って詳しく確認します。

### 日本時間未明の発生から影響拡大まで

Microsoftは公式Xアカウント（[@MSFT365Status](https://x.com/MSFT365Status)）と管理センターで、障害の状況を数十分おきに更新しました。
主な公表時刻を日本時間に直して並べると、次のような流れになります。
当初は米州だけで起きている問題とされましたが、約15分後には、全地域に影響する可能性があると訂正されています。

| 日本時間（11月13日） | Microsoftの発表内容 |

| 午前3時07分 | すべての地域でMicrosoft 365への接続に影響する可能性があると説明 |

| 午後6時14分 | 安定化の兆しはあるが、処理能力は通常に戻っていないと説明。遅れたメールの配送待ちの期限を48時間に延長 |
| 午後8時ごろ | 一部の設備で対応が完了し、通信を段階的に戻していると発表。メールボックスへの接続や遅延メールの処理が改善。断続的な影響は一部に残る |

先に起きたTeamsの障害は、Microsoftの発表では午前2時ごろに解消しています。
メールの接続障害が表面化したのはその直後ですが、Microsoftは2つの障害の関係について、現時点では明らかにしていません。
同じ日に続けて起きたため両者は混同されやすいものの、障害番号は別々に管理されています。

### 利用者に起きた症状

影響が出たのは、Web版のOutlook、デスクトップアプリ、スマートフォンアプリのほか、ほかのメールソフトが使う複数の接続方式（MAPI、ActiveSync、REST）です。
メールの送受信や予定表の表示ができない、Microsoft 365にサインインできないといった報告が相次ぎました。

障害の報告を集計する[Downdetector](https://downdetector.jp/)では、Outlookに関する報告が日本時間13日午前3時ごろに約13万件まで急増しました。
管理者向けのMicrosoft 365管理センターにもつながりにくくなり、Microsoftは公開ステータスページで情報を確認するよう呼びかけています。

## 障害の原因

Microsoftの説明は、調査が進むにつれて何度か変わりました。
当初はアクセスの増加が疑われましたが、最終的にはサーバー側の問題に焦点が移っています。
ここでは、公式発表で示された原因の説明を順に整理します。

### アクセス増ではなく「サーバーの離脱」が引き金

Microsoftは当初、複数の地域で設備に高い負荷がかかっていることが接続エラーの原因だと説明していました。
その後、この負荷はアクセスの増加ではなく、多数のサーバーが予期せず使えなくなったことで生じたものだと訂正しています。

サーバーが正常に動いているかを自動で確かめる仕組み（ヘルスチェック）に失敗したサーバーは、サービスから外されます。
外れるサーバーが増えるほど、残ったサーバーに処理が集中し、さらに不安定になるという悪循環が起きたとみられます。

### 構成変更の関与も調査中

Microsoftは当初、障害の発生と同じ時期に行われた変更は見つかっていないとしていました。
しかしその後の再調査で少数の構成変更を特定し、これらを元に戻すことで復旧を早められるかを検討していると説明しています。

さらに、影響を受けたサーバー上で中核となる処理が過負荷になり、処理能力が失われていることも突き止めました。
調査では、サーバーの状態を判定する特定の部品（コンポーネント）が、チェック失敗の発端になっている可能性も示されました。
ただし、根本原因は11月13日夜の時点で確定していません。

### 暗号化通信の処理と通信の振り分けにも負荷

日本時間13日午前10時ごろ、Microsoftは障害の出たサーバーで、安全な接続（暗号化通信）を確立する処理に負荷が集中し、処理しきれなくなっていたと説明しました。
一般に暗号化通信の開始には計算の手間がかかるため、接続のやり直しが重なると負荷が一気に高まります。

午後2時ごろには、通信を各サーバーに振り分ける装置から、裏側のサーバーへの呼び出しが急増していることも分かりました。
Microsoftは設備を増やしていますが、応答しなくなったサーバーには修正をうまく反映できていないとしています。

### サイバー攻撃の可能性は

大規模な障害が起きると、サイバー攻撃を疑う声が出がちです。
しかし今回、Microsoftは「サイバー攻撃を示す兆候はない」と説明しています。

大量の通信を送りつけてサービスを止める攻撃（DDoS攻撃）であれば、アクセスの急増として表れるのが一般的です。
Microsoftはアクセスが増えたのではなくサーバーが減ったと説明しており、この点からも攻撃の可能性は低いとみられます。

## Microsoftの対応

Microsoftは原因の特定と並行して、複数の復旧策を同時に進めました。
一部の対策は期待した効果が出なかったと認めたうえで、方針を切り替えています。
実施された対策と、今後公開される情報のポイントを確認します。

### 実施された復旧策

Microsoftは「影響を減らすためにあらゆる手段を積極的に進めている」と発表し、原因の調査と並行して段階的に複数の対策を重ねました。
日本時間13日午前7時ごろには、それまでの対策で期待した改善が得られていないと認め、復旧の進め方を改めて見直しています。
公式発表で示された主な対策は次のとおりです。

- すべてのデプロイ（更新の配信）と構成変更を一時停止
- 接続の通信を世界中の設備に振り分けて負荷を分散
- 影響を受けたサーバーの再起動と修復
- 別の方式による正常性チェックの導入
- 応答しなくなったサーバーを自動で見つけて再起動する仕組みの準備
- 最近の構成変更を元に戻すかどうかの検討

このうち別方式の正常性チェックは、一部のサーバーで効果が確認され、適用範囲が広げられました。
サーバーが順次サービスに戻ると、利用者側ではアプリが再接続したタイミングで少しずつ使えるようになっていきます。
復旧の体感には利用者ごとに差があるため、つながらない場合もしばらく時間をおいて試すのが現実的です。

### 事後報告の公開に注目

Microsoftは大きな障害のあと、原因と再発防止策をまとめた事後報告（Post-Incident Report）を管理センターで公開しています。
同じ日に起きたTeamsの障害では、速報版を2営業日以内、最終版を5営業日以内に公開するとしていました。

今回のメール障害でも、なぜサーバーがチェックに失敗したのか、構成変更がどう関わったのかが報告の焦点になります。
管理者は、障害番号EX1550543とMO1550821の更新を引き続き確認しておきましょう。

## 利用者が注意すべきこと

大規模な障害が起きている間は、焦って自分の端末の設定をいじったり、不審なメールや連絡に反応したりしやすくなります。
ここでは、個人の利用者や一般の社員が特に気をつけたい点を2つに絞って具体的に紹介します。

### 端末の設定変更や再インストールは不要

今回の障害はMicrosoft側の設備の問題で、個人のパソコンやアカウントに原因があるわけではありません。
Outlookを再インストールしたり、パスワードを変えたりしても改善しないため、障害情報を確認して復旧を待つのが基本です。
なお、Microsoftは配送が遅れているメールを守るため、配送を待つ期限を48時間に延ばしています。

ネットワーク設定を変えたり、アカウントを削除して登録し直したりすると、復旧後に別のトラブルを招くおそれがあります。
会社のアカウントであれば、自己判断で操作せず、社内の情報システム部門の案内に従いましょう。

### 障害に便乗した詐欺メールに注意

大規模な障害のあとは、復旧の手続きや再認証を装った詐欺メールが出回りやすくなります。
Microsoftを名乗って「アカウントの再確認が必要」などと案内し、偽のサインイン画面へ誘導する手口には特に注意が必要です。

Microsoftの障害対応で、利用者がメールのリンクからパスワードを入力し直す必要はありません。
不安なときは、メール内のリンクではなく、ブックマークや公式アプリからサインインして確認しましょう。
万一リンクを開いてしまった場合は、[詐欺メールを開いてしまった時の対処法](https://www.cybernote.click/2026/10/19/sagi-mail-hiraite-shimatta/)や[Microsoftアカウント乗っ取りの確認方法](https://www.cybernote.click/2026/09/24/eviltokens-microsoft-account-takeover/)を参考にしてください。

## 企業・組織が取るべき対策

メールやチャット、ファイル共有をMicrosoft 365に集約している組織ほど、今回のような障害の影響は大きくなります。
次の障害に備えて、情報の確認先、代わりの連絡手段、事後の記録の3点を今のうちに見直しておきましょう。

### 障害情報の確認先を決めておく

障害が起きたとき、多くの担当者が最初に困るのは「自社の環境だけの問題か、それともMicrosoft側の問題か」の切り分けです。
今回は肝心の管理センター自体がつながりにくくなったため、管理センター以外の確認先もあらかじめ知っておく必要があります。
主な確認先と、それぞれの特徴や使い分けは次のとおりです。

| 確認先 | 特徴・用途 |
|---|---|
| Microsoft 365管理センター「[サービス正常性](https://learn.microsoft.com/ja-jp/microsoft-365/enterprise/view-service-health)」 | 自社テナントへの影響を含む詳しい情報。障害番号で検索できる |
| 公開ステータスページ（[status.cloud.microsoft](https://status.cloud.microsoft/)） | 管理センターに入れないときの代わり。大規模障害の概要を公開 |
| 公式X（[@MSFT365Status](https://x.com/MSFT365Status)） | 更新が早く、復旧の進み具合を時系列で追いやすい |

これらの確認先は、障害対応の手順書や社内の連絡網にあらかじめ書き込んでおくと、いざというときに迷わずに済みます。
社員向けには、障害を確認した時点で一斉に周知する文面のひな形も用意しておくと、問い合わせが集中するのを防げます。
メールもTeamsも使えない前提で、周知の手段も別に決めておくのが安心です。

### メール以外の連絡手段を用意する

今回はメールとTeamsが同時に使えなくなったため、社内外の連絡が一度に止まりました。
電話や別のチャットツール、緊急連絡用の一斉通知サービスなど、Microsoft 365に頼らない連絡手段を決めておくことが重要です。

デスクトップ版Outlookで、メールを端末に保存する「キャッシュモード」を使っていれば、障害中もすでに受信したメールは読めます。
主要な取引先や社内の連絡先は、紙や別のサービスにも控えておくと安心です。

### 影響の記録と事後対応

障害中は、影響を受けた時間帯、止まった業務、取引先への影響を記録しておきましょう。
この記録は、社内への報告やMicrosoftの事後報告との突き合わせに役立ちます。

Microsoft 365には[SLA（サービス品質保証）](https://www.microsoft.com/licensing/docs/view/Service-Level-Agreements-SLA-for-Online-Services)があり、稼働率が保証の水準を下回ると、利用料の一部が返金（サービスクレジット）される場合があります。
サービスクレジットは自動では適用されず、管理者からの申請が必要です。対象となるかは契約内容によるため、事後報告の公開後に確認するとよいでしょう。

## 2026年に相次ぐMicrosoft 365障害と教訓

Microsoft 365の大規模な障害は、2026年に入ってから今回を含めて何度も起きています。
今回の障害だけを特別な出来事と見るのではなく、今後も繰り返し起きるものとして備えておくことが大切になります。

### 2026年の主な障害

2026年に報じられた主なMicrosoft 365障害を時系列で並べると、説明された原因は設定の変更、ネットワーク、認証など多岐にわたります。
共通しているのは、1か所の不具合が複数のサービスに一度に波及している点です。
なお、日付は報道や公式発表をもとにした目安で、米国時間と日本時間が混在しています。

| 時期 | 主な影響 | 説明された原因 |
|---|---|---|
| 1月22〜23日 | 北米中心にメールの送受信、検索、管理ポータルなど | 共通基盤の不具合（詳細は事後報告） |
| 6月12日（日本時間） | Copilot Chatやportal.office.comにアクセス不能 | 最近の変更。元に戻して解消 |
| 7月23日 | 北米の一部経路でTeams、SharePoint、OneDriveなど | 特定のネットワーク経路の問題 |
| 8月31日〜9月1日 | 複数サービスで長時間の障害 | 複数サービスが使う認証の中核設定の問題 |
| 11月12〜13日 | Exchange Online、Teams、Copilotなど | 多数のサーバーが正常性チェックに失敗し負荷が集中 |

表のとおり、大きな障害は数か月おきに起きており、復旧まで半日以上かかるケースも決して珍しくありません。
今回のように、サーバーが外れることで残りに負荷が集中し、被害が広がる連鎖は大規模なクラウドで起きやすい典型的な例です。
クラウドを使う側は、サービスが止まることを前提に業務を組み立てる必要があります。

### 集中依存のリスクをどう減らすか

メール、チャット、ファイル共有、セキュリティ監視を1つのサービスにまとめると、管理はしやすくなります。
その一方で、そのサービスが止まると業務全体が止まるという弱点を抱えることになります。

すべてを分散させるのは現実的ではありませんが、止まったときの代わりの手段を決めておくことはすぐにできます。
今回の障害を機に、Microsoft 365が数時間使えない想定で業務継続の手順を点検しておきましょう。
あわせて、11月の更新で悪用が確認された[OutlookのCVE-2026-124194](https://www.cybernote.click/2026/11/11/microsoft-outlook-cve-2026-124194-ntlm-spoofing-kev/)など、障害とは別のセキュリティ更新が後回しになっていないかも確認しておくと安心です。

## まとめ

2026年11月13日未明に起きたMicrosoft 365の大規模障害では、Outlookのメールを中心に、TeamsやSharePoint Online、Copilotなどへ影響が広がりました。
Microsoftは、多数のサーバーが正常性チェックに失敗して使えなくなり、残りの設備に負荷が集中したと説明しています。

根本原因は調査中で、Microsoftはサイバー攻撃を示す兆候はないとしています。
利用者は端末をいじらず公式情報を確認し、障害に便乗した詐欺メールに注意しましょう。
組織は、確認先や代わりの連絡手段を事前に決め、次の障害に備えることが大切です。
