# 【続報】IDCフロンティア第4報、ソフトバンクと連携した対応体制を公表｜495社・自治体に影響

IDCフロンティアは2026年10月9日、IDCFクラウドの不正アクセスによる障害について第4報を公表しました。今回明らかになったのは、親会社のソフトバンクと連携した顧客対応・調査・復旧の体制です。障害は10月7日午前3時40分頃から発生しており、影響範囲は495の企業・自治体です。

第4報は対応体制に関する発表であり、サービスの全面復旧や情報漏えいの有無、侵入経路、攻撃者について新たな確定情報を示したものではありません。10月8日の第3報で示された、対象4ゾーンの顧客データの取り出し・復元が困難との見通しについても、変更は公表されていません。

## IDCFクラウドのランサムウェア攻撃で何が起きたのか

障害が始まったのは10月7日午前3時40分頃です。IDCフロンティアは同日の第2報で第三者によるランサムウェア攻撃が原因と公表し、翌8日に第3報を発表しました。

第3報では影響を受けるゾーンやデータ復元の見通しが具体的に示されています。公表済みの内容を表にまとめます。

| 項目 | 2026年10月9日時点の公式発表 |
| --- | --- |
| 発生日時 | 10月7日午前3時40分頃、継続中 |
| 対象 | 東日本リージョン1のtesla・henry・pascal・jouleゾーン |
| 発生事象 | 仮想サーバーの停止、再起動不可 |
| 原因 | 第三者によるランサムウェア攻撃 |
| 影響 | 495の企業・自治体 |
| 対応体制 | ソフトバンクと連携した緊急対策本部。顧客支援と調査・復旧対応を実施 |
| 顧客データ | 対象4ゾーンで取り出し・復元が困難との見通し |
| 復元方法 | 顧客自身が保持するバックアップからのみ可能との見解 |
| 情報漏えい | 外部流出が確認されたとの公表なし |
| 侵入経路 | 調査中 |

495という数字は影響を受ける契約先の数であり、全組織で同じ被害が確定したことを意味しません。データの暗号化範囲や攻撃グループ、身代金要求の有無も明らかにされていません。

## 第4報で公表されたソフトバンクとの対応体制

10月9日の第4報によると、IDCフロンティアは10月7日午前9時に緊急対策本部を設置し、親会社のソフトバンクと連携して対応を進めています。

顧客対応はソフトバンクの法人部門を窓口として実施し、バックアップ手順の案内や移行環境の提案、顧客の要望に応じた仮想サーバーの起動・停止作業の代行を行います。

調査・復旧については、IDCフロンティアの技術部門を中心にソフトバンクの技術部門が支援し、詳細調査と復旧計画の策定・実行を進めています。外部のセキュリティ専門企業とも連携して調査を実施します。また、監督省庁や警察など関係機関への報告・相談も進めているとしています。

この発表は対応体制を説明したもので、全面復旧や侵入経路の特定、情報漏えいの有無を新たに確定したものではありません。

## 第3報で判明した顧客データの復元困難

今回の続報で最も重要なのは、対象4ゾーンのデータについて取り出し・復元が困難との見通しが示されたことです。クラウド基盤の障害が解消すれば元のデータも必ず戻る、とは限らない状況が明らかになりました。

IDCフロンティアは対象ゾーンの利用者に対し、別環境を準備して再構築するよう案内しています。データの復元は利用者が自ら保持するバックアップを使って実施する方針です。バックアップが存在するか、利用可能な状態かによって、各社の復旧作業の難しさは異なります。

ただし、すべての顧客データが完全に消失したと確定したわけではありません。現時点の発表は取り出し・復元が困難という見通しであり、最終的なデータ消失の確定情報ではありません。

## 他リージョンへの影響と管理コンソール停止

東日本リージョン1のradian・newtonゾーン、東日本リージョン2・3、西日本リージョン1については、第3報の時点で不正アクセスは確認されていません。ただし、安全性の確認と被害拡大防止のため、他リージョンの顧客向け管理コンソールも停止されています。

これらの利用者には、自社でデータのバックアップを取得するよう案内しています。管理コンソール停止中の仮想サーバーの起動・停止などは、IDCフロンティアが利用者の要望に応じて代行しています。

ネットワークの遮断と管理コンソール停止は10月7日に実施されました。侵入経路の特定や各リージョンの安全性調査は外部の専門企業と連携して継続中です。なお、IDCFクラウド Type SとIDCFプライベートクラウドは今回の事象の対象外とされています。

## 情報漏えいは確認されたのか

データを取り出せないことと、情報が外部へ漏れたことは別です。10月9日の第4報でも、情報漏えいが確認されたとの新たな発表はありません。一方、漏えいがなかったと断定されたわけでもありません。第4報は対応体制の説明が中心であり、情報漏えいの有無は未確定事項として扱う必要があります。

IDCフロンティアは監督省庁と警視庁に報告したことも公表しました。侵入経路、データの暗号化範囲、攻撃グループについて、未公表の事項を推測で補うことは避ける必要があります。

## 利用企業が確認したい復旧準備

IDCFクラウドの利用企業は、まず公式の個別連絡と障害情報を確認する必要があります。特に対象4ゾーンの利用者は、クラウド基盤とは別の環境にバックアップが保存されているか、実際に復元できるかを確認することが重要です。

代替環境の構築手順、認証情報、取引先への連絡方法、復旧作業に必要な担当者や委託先も整理しておきましょう。バックアップがあっても、必要な設定や手順が不足していると業務再開まで時間がかかることがあります。
