# デジタル庁GSSに不正アクセス｜24.6万件漏えいの可能性とVPN脆弱性

デジタル庁は2026年9月11日、政府共通の業務実施環境であるガバメントソリューションサービス（GSS）が外部から不正アクセスを受け、職員などの個人情報約24.6万件が漏えいした可能性があると公表しました。侵入経路は保守運用に使われていたVPN機器の脆弱性で、攻撃者は保守運用担当者のアカウントを悪用し、サーバー上の大量のファイルにアクセスしていたとされています。マイナンバーや金融機関口座情報は含まれず、一般の方の個人情報も対象外です。本記事では公表された事実を整理し、対象者が注意すべき点と企業が学べる脆弱性管理の論点を解説します。

## 事案の概要と漏えいした可能性がある情報

GSSは各府省庁の業務用PCやネットワークをまとめて提供する政府共通の業務実施環境です。今回の事案では、外部からVPN機器を経由して侵入され、内部の保守運用アカウントが悪用されたことで、個人情報を含むファイルへの大量アクセスが発生しました。

### 公表された事案の骨子

デジタル庁の発表から確認できるのは、侵入経路がVPN機器の既知脆弱性だったこと、保守運用担当者のアカウントが使われたこと、外部専門事業者と調査した結果として個人情報の漏えい可能性を確認したことです。一方、攻撃者像やVPN製品名、CVE番号は公表されていません。現時点で確認できる事実を整理すると次のとおりです。

| 項目 | 内容 |
| --- | --- |
| 公表日 | 2026年9月11日 |
| 対象システム | ガバメントソリューションサービス（GSS） |
| 侵入経路 | ネットワーク接続機器（VPN）の脆弱性 |
| 漏えいの可能性 | 約24.6万件 |
| 二次被害 | 現時点で確認されていない |

侵入が外部からの通信だけで完結せず、内部に入られた後に保守運用担当者のアカウントが悪用された点は重要です。外部公開機器の脆弱性対策だけでなく、侵入後のアカウント利用を監視し、異常なアクセス量や接続元を検知する仕組みが被害抑制に直結します。VPN製品を利用する組織は、[OpenVPNの脆弱性事例](https://www.cybernote.click/2026/09/13/openvpn-cve-2026-13379-windows/)も含め、公開範囲と更新状況を継続的に確認する必要があります。

### 漏えいの可能性がある個人情報

対象となった情報は、GSS利用者登録などの申請書に記載された内容が中心です。電話番号や住所の多くは個人宅ではなく、庁舎所在地や公務用の連絡先が大半と説明されています。ただし氏名とメールアドレスの組み合わせは、所属先を装ったなりすましや標的型メールに利用される可能性があるため、二次被害への警戒は必要です。

| 属性 | 件数（重複あり） |
| --- | ---: |
| 氏名 | 約23.6万件 |
| メールアドレス | 約23.1万件 |
| 電話番号 | 約9.4万件 |
| 住所 | 約0.1万件 |

内訳はGSS利用機関の職員や業務に携わった公務員等が約18.9万件、事業者および個人が約5.7万件です。マイナンバー、金融機関口座情報、年金番号などは含まれていないと確認されています。現時点で本件に起因する二次被害も確認されていませんが、漏えいした可能性のある氏名や業務用メールアドレスを手掛かりに、デジタル庁や関係機関を装う連絡が作られる可能性は残ります。

## 侵入経路となったVPN機器の既知脆弱性

セキュリティ担当者にとって重要なのは、悪用された脆弱性が未知のものではなかった点です。デジタル庁は攻撃前から脆弱性を把握し、一般的な対応より早く対処を進めていたものの、修正プログラムの適用前に悪用されたと説明しています。

### 深刻度「中」でも修正前に悪用された

悪用された脆弱性の当初評価はCVSSで中（Medium）レベルでした。CVSSは影響度や攻撃条件を整理するうえで重要な指標ですが、実際に攻撃者が使っているか、対象機器がインターネットから到達可能か、組織内でどの権限を持つかといった運用上の条件までは単独では表しません。今回の事案は、スコアだけで優先順位を固定すると対応が間に合わない場合があることを示しています。

脆弱性対応では、CVSSに加えて実悪用の有無や公開範囲、機器の重要度を組み合わせることが重要です。[CISA KEVに追加された実悪用事例](https://www.cybernote.click/2026/09/04/jfrog-artifactory-cve-2026-82329-auth-bypass-kev/)のように、悪用状況を優先順位へ反映する考え方は、政府機関だけでなく一般企業でも有効です。

### 製品名やCVE番号は公表されていない

デジタル庁は今後のセキュリティ確保に支障を及ぼすおそれがあるとして、脆弱性の具体的内容やVPN製品名を公表していません。Q&Aで明らかにされているのは、既知の脆弱性であり、当初の評価がMediumだったことまでです。外部では特定製品やCVE番号を推測する情報もありますが、公式に確認されていない以上、本記事では特定しません。

## デジタル庁の対応と対象者が注意すべきこと

デジタル庁はVPN機器への修正プログラム適用、関係アカウントの停止・認証情報変更、侵害機器と外部との通信遮断、監視強化を実施しました。対象者には順次個別連絡を行うとしており、現時点では二次被害は確認されていません。

発表された経緯を見ると、6月25日の大量ファイルアクセス検知から侵入経路の特定、個人情報保護委員会への報告、9月11日の公表まで段階的に調査が進められています。検知直後には影響範囲が分からず、侵入経路の分析や対象情報の特定に時間を要したと説明されています。公表までの主な時系列は次のとおりです。確認上も重要です。

- 6月25日：保守運用担当者アカウントによる大量ファイルアクセスを検知し調査開始
- 7月9日：VPN機器の脆弱性を悪用した不正アクセスと判明し、アカウント停止と通信遮断
- 7月15日：個人情報保護委員会へ報告
- 9月11日：漏えいの可能性を公表

公表後に特に注意したいのは、この事案そのものを口実にしたフィッシングやなりすましです。デジタル庁は、メールや電話でパスワード、クレジットカード情報などを聞くことはないと案内しています。対象確認や補償を装う連絡が届いても、本文中のリンクや添付ファイルから手続きを進めず、公式サイトや既知の窓口を自分で開いて確認してください。組織側も、[外部公開機器の重大脆弱性事例](https://www.cybernote.click/2026/09/11/cisco-secure-fmc-cve-2026-20079-auth-bypass-rce-exploited/)と同様に、更新だけでなく侵害有無の確認までを一連の対応として扱うことが重要です。

## 企業・組織が学ぶべき3つの教訓

今回の事案は政府機関だけに固有の問題ではありません。外部公開のVPN機器、強い権限を持つ保守運用アカウント、CVSSを使った脆弱性の優先順位づけは、多くの企業でも共通する管理対象です。自組織に置き換えて点検すべき論点があります。

### CVSSスコアだけで優先順位を決めない

CVSSの基本値は脆弱性の技術的な深刻度を比較するための共通指標です。しかし、実際の攻撃状況やインターネットからの到達性、対象システムの重要度は別に評価する必要があります。Mediumでも悪用される可能性があるため、実悪用情報、公開範囲、資産の重要度を加えた優先順位づけが必要です。

### 保守運用アカウントを侵害の起点として扱う

保守運用アカウントは広い権限を持つことが多く、侵害された場合は被害が拡大しやすくなります。多要素認証、接続元制限、必要最小限の権限に加え、普段と異なる時間帯や大量のファイルアクセスを検知する監視を組み合わせることが重要です。アカウント停止だけでなく、認証情報の変更や関連ログの確認まで手順化しておく必要があります。

### ゼロトラストでも侵入前提の設計を保つ

GSSはゼロトラストネットワークアーキテクチャを採用していましたが、それでも不正アクセスと情報漏えいの可能性が生じました。ゼロトラストは製品を導入すれば完了する考え方ではなく、接続ごとの検証、権限管理、監視、封じ込めを継続する設計です。侵入を完全に防ぐことだけでなく、侵入後に異常を早く見つけ、影響範囲を小さく抑える運用まで含めて評価する必要があります。

## まとめ

今回の事案は、既知だったVPN機器の脆弱性が修正前に悪用され、保守運用担当者のアカウント利用を経て、約24.6万件の個人情報が漏えいした可能性があるものです。マイナンバーや口座情報は含まれず、一般の国民の個人情報も対象外ですが、氏名やメールアドレスが多数含まれるため、対象者はなりすましやフィッシングへの警戒を続ける必要があります。組織側では、CVSSだけに依存しない優先順位づけ、保守運用アカウントの継続監視、侵入後の検知と封じ込めを組み合わせることが重要です。今回の事案を、自社のVPN機器や外部公開機器、特権アカウントの管理方法を見直す具体的な点検材料として活用できます。
