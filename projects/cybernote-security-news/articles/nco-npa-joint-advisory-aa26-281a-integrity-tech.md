# 日本など7か国が国際アドバイザリーに共同署名、中国政府関連とされる攻撃者の手口と対策

国境を越えた情報窃取について、各国の政府機関が連名で警告を出しました。米連邦捜査局（FBI）などが作成したアドバイザリーに、日本を含む7か国の10機関が署名しています。文書は、中国に拠点を置く企業Integrity Technology Group（永信至誠科技集団）と、同社が支援するとされる攻撃者の手口を、FBIの捜査で得た技術的証拠に基づいて整理したものです。公表と同時に、米国は攻撃基盤の差し押さえと脆弱性カタログの更新も行いました。この記事では、10月11日時点の情報をもとに、発表の概要、公表後に判明した動き、攻撃の流れ、悪用された脆弱性、組織が確認したい対策を解説します。

## 各国機関が共同アドバイザリーを公表、何が発表されたのか

発表されたのは、中国政府と関連するとされる攻撃者の手口と、その検知・防御方法をまとめた技術文書です。米国での公開は2026年10月8日、日本での公表は翌9日でした。まず文書の概要と、情報の根拠を確認します。

### 文書の概要

アドバイザリーの文書番号はAA26-281Aで、全58ページのうち19ページ以降は侵害指標などの付録です。日本側では、国家サイバー統括室と警察庁が連名で報道資料を出し、両機関のサイトに日本語の概要と英文の原文を掲載しました。国家サイバー統括室が掲載する英文の版は10月8日付の初版で、10月11日時点で改訂は確認できません。主な項目を表にまとめます。

| 項目 | 内容 |
| --- | --- |
| 文書番号 | AA26-281A |
| 公開日 | 米国での公開：2026年10月8日／日本での公表：10月9日 |
| 署名機関 | 米国（FBI、CISA、NSA）、英国、豪州、カナダ、日本（警察庁、国家サイバー統括室）、ニュージーランド、スペインの計10機関 |
| 標的とされた分野 | 政府、重要製造業、医療・公衆衛生、情報技術など |
| 主な対策 | 不要なサービス・ポートの無効化、Web入力値の無害化、多要素認証 |

署名機関は、防御担当者に2つのことを求めています。自組織に侵害の痕跡がないかを調べることと、同種の攻撃への防御を強化することです。日本側の報道資料は、今後もサイバー安全保障と同盟国・同志国との連携の強化に努めるとしています。日本国内の組織だけに向けた個別の指示や期限は含まれておらず、対応は各組織の判断に委ねられています。

### 情報の根拠と位置づけ

記載内容は、Integrity Technology Groupに関するFBIの複数の捜査で回収・観測された技術的証拠に基づくとされています。推奨されている対策は勧告であり、法令上の義務ではありません。

## 公表と同時に進んだ米国の措置

アドバイザリーの公表は、単独の注意喚起ではありませんでした。米国は同じ10月8日に、攻撃用ツールを支える基盤の差し押さえと、脆弱性カタログの更新を行っています。日本に関わる情報も含まれるため、公表後に判明した内容を整理します。

### ドメイン7件の差し押さえ

米司法省とFBIは10月8日、裁判所の許可を得て、2つの攻撃用ツールに関わるドメイン7件を差し押さえたと発表しました。対象は、標的の弱点を探すMicroScanと、標的型メールによる侵入を助けるFishHubです。

同省によると、Integrity Technology Groupの攻撃基盤を技術的に妨害した措置の公表は、2024年9月に続いて2度目です。前回は、20万台を超える機器で構成されたボットネットが無力化されました。報道によると、差し押さえられたドメインの1つは、アドバイザリーにSoftEtherの接続先として載っている98aiblog[.]comです。

### 日本の空港もスキャンの対象に

米司法省の発表は、裁判所に提出された文書に基づき、MicroScanによる脆弱性スキャンの対象を挙げています。米国の電力会社、多国籍の非政府組織、台湾のガス・電力会社と大学に加え、日本とポーランドの空港が含まれていました。報道によると、スキャンの時期は2022年です。

ただし、示されているのはスキャンの対象になったという事実です。日本の空港への侵入や情報窃取が確認されたとは書かれておらず、発表文に空港名の記載もありません。同省は、日本の警察庁から実質的な支援を受けたとも述べています。

### 悪用済み脆弱性カタログへの追加

アドバイザリーの付録は、8件の脆弱性のうち5件が、米CISAの悪用済み脆弱性カタログ（KEV）に新たに追加されたと注記しています。KEVカタログで確認できたCVE-2015-3306の場合、追加日は10月8日、米連邦政府機関の対応期限は3日後の10月11日です。

この期限は米連邦政府機関を対象とするもので、日本の組織に義務は生じません。それでも、悪用が確認済みという扱いは、対応の優先度を決める材料になります。このうち[ProFTPDのCVE-2015-3306](https://www.cybernote.click/2026/10/09/proftpd-cve-2015-3306-kev-update/)と[Apache StrutsのCVE-2016-3081](https://www.cybernote.click/2026/10/09/apache-struts-cve-2016-3081-kev-update/)は、個別の記事で対応方法を解説しています。

## どのような攻撃者なのか

署名機関が名指ししたのは、中国に拠点を置く営利企業と、同社の支援を受けるとされる攻撃者です。ここでは企業の位置づけと、標的になった分野・地域を整理します。いずれも署名機関の評価として示された内容です。

### 名指しされた企業

アドバイザリーによると、Integrity Technology Groupは中国政府とつながりのある営利企業です。攻撃用ツールの入手や開発、インフラの調達と運用、世界各地のネットワークへの侵入を担う人員を雇用しているとされます。

同社が支援する攻撃者の手口は、Flax Typhoon、Ethereal Panda、Red Juliettなどの名称で知られる活動と一致すると説明されています。ただし、セキュリティ企業ごとに追跡方法が異なるため、これらの呼称と一対一で対応するとは限らないとの注記があります。

### 標的の分野と地域

標的として挙げられたのは、米国の重要インフラ4分野（政府、重要製造業、医療・公衆衛生、情報技術）です。米国の法執行機関、教育機関、宗教団体のほか、東南アジア、アフリカ、北米の組織も狙われたとされています。

メールデータの窃取では、東南アジアの政府機関、法執行機関、医療機関、宗教機関が被害に遭ったと記載されています。日本の組織が被害を受けたという記述は、アドバイザリーにも日本側の報道資料にもありません。

## 攻撃はどのように進むのか

攻撃は、公開システムの弱点探しから始まり、侵入、居座り、情報の持ち出しへと進みます。特徴は、公開されているツールや正規のソフトウェアを多用する点です。段階ごとの手口と、防御側が見るべき点を整理します。

### 偵察から侵入まで

NmapやWPScanなど公開されている調査ツールで、ネットワークやWebアプリケーションの脆弱性を探します。早ければ2017年から、1,300以上の検査スクリプトを備えたMicroScanというツールも使っていたとされます。

侵入には、攻撃コードを組み込んだコマンドラインツールのほか、クロスサイトスクリプティング（Webページに不正なスクリプトを埋め込む攻撃）が使われました。偽のログイン欄を表示させ、IDとパスワードを入力させる手口です。Microsoft Exchangeのメールアカウントには、パスワードスプレー（よくあるパスワードを多数のアカウントに試す攻撃）が仕掛けられました。

### 居座りと情報の持ち出し

侵入後は、正規のVPNソフトウェアであるSoftEtherを端末に導入し、外部から継続的に接続できる状態を作ります。実行ファイルにはconhost.exeなどWindows標準のプログラムと同じ名前が付けられ、検知を逃れようとしていました。

情報の収集では、メールを自動で取得して外部サーバーへ送るスクリプトが確認されています。DCSync（認証基盤であるActive Directoryの複製機能を悪用し、認証情報を取り出す手法）も使われました。

### 段階ごとの整理

ここまでに見てきた攻撃全体の流れを、表の形で偵察、初期侵入、居座り、収集・持ち出しの4段階にまとめました。左から2列目はアドバイザリーに書かれた手口で、右列の着眼点は、同じ文書の推奨対策をもとに本記事が対応づけたものです。自組織のどの記録を見れば兆候に気づけるかを考える手がかりとして使ってください。

| 段階 | 手口 | 防御側の着眼点 |
| --- | --- | --- |
| 偵察 | 公開ツールやMicroScanによる脆弱性の探索 | 短時間の大量アクセス、外部に公開している不要なポート |
| 初期侵入 | 既知の脆弱性の悪用、クロスサイトスクリプティング、パスワードスプレー | 修正プログラムの適用状況、認証の失敗と成功の記録 |
| 居座り | SoftEtherの導入、正規プログラム名の偽装 | 許可していないVPNソフトウェア、標準と異なる場所にある実行ファイル |
| 収集・持ち出し | メールの自動取得、DCSync | 想定外のActive Directory複製、平常時より多い外部への送信 |

どの段階でも、未知の高度な技術より、既知の弱点と正規ツールの悪用が中心です。裏を返せば、特別な製品を新たに入れなくても、修正プログラムの管理や認証記録の確認といった基本的な運用が検知の機会になります。まずは、表の着眼点に対応するログを取得し、調査に足る期間保存できているかを確かめておくとよいでしょう。

## 悪用された脆弱性と、狙われやすい環境

付録には、悪用に成功したとされる8件の脆弱性が載っています。CVE番号の年は2014年から2023年までで、すでに修正プログラムが出ている古いものが多いことが特徴です。一覧と、狙われやすい環境を順に確認します。

### 悪用が確認された8件

対象は、Webサーバーやリモート接続機器、開発基盤など幅広い製品で、特定の業種や組織の規模に限られません。右端の列は、米CISAの悪用済み脆弱性カタログでの扱いを示しています。新規追加の5件は、アドバイザリーの付録が今回新たに加わったと注記したもので、残る3件は報道によると以前から掲載されていました。

| CVE番号 | 製品 | 種類 | KEVでの扱い |
| --- | --- | --- | --- |
| CVE-2014-6278 | GNU Bash | リモートコード実行 | 掲載済み |
| CVE-2015-3306 | ProFTPD | 不正な読み取り | 新規追加 |
| CVE-2015-5477 | ISC BIND 9 | サービス拒否 | 新規追加 |
| CVE-2016-3081 | Apache Struts | リモートコード実行 | 新規追加 |
| CVE-2019-11510 | Pulse Connect Secure | 不正な読み取り | 掲載済み |
| CVE-2021-22205 | GitLab | リモートコード実行 | 掲載済み |

影響を受けるバージョンは製品ごとに異なるため、該当製品を使っている場合はアドバイザリーの付録Bで確認してください。深刻度の数値は文書に記載されていません。8件はいずれも修正プログラムが提供済みなので、該当する機器が見つかった場合は、更新またはサポート対象の製品への入れ替えが対応の基本になると考えられます。

### 狙われやすい環境

アドバイザリーは、攻撃者がGitHubなどで公開されているツールを使うことから、より脆弱な標的を探す傾向があると分析しています。更新が止まったサーバーや、存在を忘れられた公開システムは見つけられやすい環境です。

修正プログラムの公開から悪用までの時間については、[既知の脆弱性が狙われる背景を整理した記事](https://www.cybernote.click/2026/10/05/why-cyber-incidents-ai-patch-tuesday/)でも解説しています。

## 組織が確認すべき対策

アドバイザリーは22項目の対策を挙げ、そのうち3つを主要な対策として冒頭に示しています。ここでは、攻撃の手口に直結する項目を中心に5つを選びました。選定と順序は本記事の判断です。侵害が疑われる場合の手順もあわせて確認します。

### 優先して確認したい5項目

上の3つはアドバイザリーが主要な対策として掲げたもので、残る2つは22項目の中から本記事が選びました。いずれも今回の手口に直接対応する対策で、多くは追加の費用をかけずに今日からでも着手できます。外部に公開しているシステムと、メールやリモート接続の認証から点検を始めると、攻撃の入り口を先にふさげます。

| 対策 | 確認すること |
| --- | --- |
| 不要なサービス・ポートの無効化 | リモート接続やファイル共有など、使っていない機能が外部に公開されていないか |
| Web入力値の無害化 | Webアプリケーションが、入力された文字列をそのまま画面に出力していないか |
| 多要素認証の適用 | Webメール、VPN、重要システムに接続するアカウントで有効になっているか |
| 修正プログラムの適用とサポート終了製品の入れ替え | 上記8件の該当製品を含め、更新が止まった機器が残っていないか |
| 監視 | 想定外のActive Directory複製、通常の勤務時間外のログイン、平常時より多い外部への送信がないか |

右列の確認内容は、アドバイザリーの記述を本記事が点検しやすい項目の形に言い換えたものです。22項目には、このほかネットワークの分割、バックアップの保管、利用者への教育なども含まれます。自組織の環境に合う項目を漏れなく選ぶためにも、全体は一次ソースの14ページ以降であらためて確認することをおすすめします。

### 侵害が疑われる場合

アドバイザリーは対応の順序も示しています。侵害された端末を特定して隔離し、ログなどを集めて侵入範囲を調べ、各国の定めに従って報告したうえで、攻撃者を排除し、防御を強化する流れです。

日本の組織の報告先には、国家サイバー統括室へのメールと、警察庁のサイバー事案に関する相談窓口が挙げられています。侵入後の動きを複数のログから追う考え方は、[攻撃の自動化と検知を扱った記事](https://www.cybernote.click/2026/10/07/ai-autonomous-cyberattack-glm-5-3-2026/)でも紹介しています。なお、今回のアドバイザリーはAIの利用には触れていません。

## 侵害指標を使うときの注意点

付録Aには、ドメイン名、IPアドレス、ツールのハッシュ値といった侵害指標（攻撃の痕跡を示す情報）が約40ページにわたって掲載されています。ただし、そのまま遮断リストに入れる使い方は勧められていません。理由と使い方を確認します。

### 遮断の前に精査する

侵害指標の一部は2016年までさかのぼる古い情報です。署名機関自身が、遮断などの措置の前に精査するよう求めています。古いIPアドレスは、すでに無関係の利用者に割り当てられている可能性があるためです。

差し押さえられたドメインは攻撃者の手を離れましたが、過去の通信を調べる手がかりとしての価値は変わりません。

### ログ調査での使い方

たとえば、メールを窃取するスクリプトの通信先としてnatcloudservice[.]comが、偽装された実行ファイルの通信先としてdns.studiocloud[.]xyzが挙げられています。各指標には初回と最終の観測日が付いているため、自組織のログの保存期間と照らして調査範囲を決めるとよいでしょう。
