# AIの「社内規程」が改訂された――Model Specをセキュリティ担当者はどう読むか

## はじめに

2026年10月29日（米国時間）、[OpenAI](https://openai.com/)はAIモデルの望ましい振る舞いを定めた公開文書「Model Spec」の改訂版を公開しました。
ChatGPTやAPIで動くモデルが、何を優先し、どこで踏みとどまるべきかを示した文書です。

ニュースとしては「5つの価値で再編」「文体の指針を削除」といった見出しが目立ちます。
しかしセキュリティの立場から読むと、この文書は別の顔を持っています。
それは、AIに渡す権限と、その止め方を定めた「AIの社内規程」という顔です。

本コラムでは、今回の改訂をセキュリティ担当者の目線で読み解きます。
そのうえで、企業がAIを業務に組み込むときに何を考えるべきかを整理します。

## Model Specとは何か、今回なにが変わったか

Model Specは、モデルの訓練や評価の基準となる行動指針です。
2024年5月に初版が公開され、以降も改訂が重ねられてきました。

今回の改訂では、指針全体が5つの価値を軸に組み直されました。
人間の意図への忠実さ、害の最小化、誠実さと透明性、人間の主体性、思いやりの5つです。

あわせて、会話や記憶（メモリ）といった文脈の扱い、人間による監督、副作用の伝え方に関する指針が加わりました。
一方で、細かな文体の指針は大半が廃止されています。
ルールを増やすというより、「判断の拠り所」を入れ替えた改訂だと言えます。

## セキュリティ担当者が注目すべき3つのポイント

改訂内容のうち、企業のセキュリティに直結するのは「誰の指示に従うか」「記憶をどう扱うか」「人間がどう止められるか」の3点です。
いずれも、AIエージェントが自律的に作業する時代に欠かせない論点です。

### ①指揮系統：外部の文章は「命令」ではない

Model Specは、指示の優先順位を階層として定めています。
最上位にModel Spec自身が置かれ、その下にOpenAI、開発者、ユーザーと続く構造です。

重要なのは、Webページやツールの出力、引用された文書は、原則として権限を持たないとされている点です。
AIが読み込んだ文章に「この指示に従え」と書かれていても、それは命令ではなくデータとして扱うべきだという考え方です。

これは、プロンプトインジェクション対策の基本そのものです。
攻撃者がWebページやメールに仕込んだ指示で、AIを乗っ取る手口はすでに現実の脅威になっています。
提供元の規範がこの線引きを明文化していることは、利用企業にとっても心強い材料です。

### ②文脈と記憶：便利さと情報漏えいは紙一重

新たに設けられた節では、会話やメモリ、パーソナライゼーションの扱いが整理されました。
関連性と釣り合いを考えて文脈を使い、プライバシーと利用者による制御を尊重することが求められています。

記憶機能は便利な半面、セキュリティ上の新しいリスクも生みます。
過去の会話に含まれた機密情報が、別の場面で不用意に持ち出されるおそれがあるからです。
また、悪意ある入力が記憶に残り、後の応答をゆがめる「メモリ汚染」も懸念されています。

情報の出所や範囲、新しさを考慮し、利用者がそれを確認・修正できるようにする。
この方向性は、企業が社内でAIを使う際のデータ管理ルールにもそのまま応用できます。

### ③人間の監督：AIを「止められる」ことが前提

今回の改訂では、人間による監督と訂正を支援することが明記されました。
AIは監視や評価、訂正、停止に応じ、それを妨げたり回避したりしてはならないという考え方です。

さらに、AIが自律的に動く際は、使ってよい道具や許容できる副作用、確認が必要な場面を事前に取り決めることが求められています。
これは、セキュリティの世界で長く言われてきた「最小権限の原則」をAIに当てはめたものと言えます。

AIエージェントに、メール送信やファイル操作、外部サービスへのアクセスを任せる企業は増えています。
権限の範囲と終了条件を決めずに走らせることは、鍵を預けたまま行き先を告げないのと同じです。

## それでも「AI任せ」にできない理由

ここまで読むと、AIの安全性は提供元に任せておけばよいと感じるかもしれません。
しかし、それは危険な誤解です。

OpenAI自身が、現行のモデルはまだModel Specを完全には反映していないと説明しています。
つまりこの文書は、「すでに守られている基準」ではなく「目指す姿」を示したものです。
OpenAIが公表している評価でも、最も成績のよいモデルですら、一定の割合で基準から外れる結果が出ています。

規範はあくまで目標であり、保証ではありません。
AIの「良心」に期待するのではなく、人間側の統制とセットで設計することが欠かせないのです。

## 企業が今やるべきこと

Model Specの改訂は、企業にとって自社のAI利用ルールを見直す好機でもあります。
提供元が示した考え方を手がかりに、次のような点を点検しておくとよいでしょう。

- 社内のAI利用ルールに、外部コンテンツ由来の指示を実行させない方針を盛り込む
- AIエージェントに渡す権限を業務に必要な範囲に絞り、送信・削除などの操作には人の承認を挟む
- 記憶機能に入力してよい情報の範囲を定め、機密情報の扱いを明確にする
- AIの操作ログを残し、定期的に確認できる体制を整える

いずれも、目新しい対策ではありません。
アクセス制御、承認フロー、ログ監視といった、従来のセキュリティ対策の延長線上にあるものです。
AIを「新しい種類の従業員」とみなし、人と同じ統制の枠組みに組み込むことが近道だと言えます。

## まとめ

今回のModel Spec改訂は、AIが何を優先し、どこで人間に判断を委ねるかを改めて示したものです。
指揮系統、記憶の扱い、人間の監督という3つの論点は、いずれも企業のセキュリティと深く結びついています。

ただし、提供元の規範はAIの安全を保証するものではありません。
OpenAI自身が認めるように、モデルは規範に追いつく途中にあります。

だからこそ利用する側には、AIを信頼しつつも、権限を絞り、記録を残し、いつでも止められる状態を保つ姿勢が求められます。
AIの「社内規程」が整っていくいまこそ、自社の規程も見直してみてはいかがでしょうか。
