# [テスト] CyberNote セキュリティニュース投稿テスト

このページは、CyberNoteの短編セキュリティニュースを、候補選定から記事保存、アイキャッチ登録、WordPress下書き作成まで確認するためのテスト記事です。実際の事件や製品の脆弱性を扱う記事ではなく、運用経路が正しく動くかを確認する目的で作成しています。テスト対象日は通常の記事と分け、公開処理の対象を明示的に指定します。

## 何を確認するテストか

今回の確認では、管理簿に記録したNo、タイトル、スラッグ、本文ファイル、画像ファイルが正しく結び付くかを確認します。選択処理では、公開予定日が一致する行だけを読み込み、生成済みで、停止されていない記事から1件を選びます。話題性スコアが同じ場合はNoの小さい行を優先するため、同じ日に複数候補が残っても投稿対象を一つに絞れます。

記事本文はMarkdownで保存し、文字数、序文の長さ、H2見出し、リンクの有無を確認します。実運用では、ニュースの発表日、影響範囲、利用者が取るべき対策を一次情報と照合してから生成します。確認できない内容を補ったり、攻撃者の主張だけで被害を断定したりしないことが重要です。

## WordPressへの反映

18時30分の下書き処理では、本文とアイキャッチをWordPressへ登録し、投稿ステータスを下書きにします。dry-runを指定した場合は、記事と画像を検査するだけで、WordPressへの投稿や画像アップロードは行いません。まずこのモードで、対象選択と品質チェックが成功することを確認します。

本番の下書き登録後は、管理画面でタイトル、本文、リンク、アイキャッチ、カテゴリーを確認できます。修正が必要な場合は19時までにワークフローを停止してください。19時の公開処理は、確認済みの投稿本文を作り直さず、対象投稿のステータスだけを公開へ変更します。

## 確認先

WordPress投稿に関する一般的な確認先は[CyberNoteトップ](/)です。セキュリティ情報の調査では、[JPCERT/CC](https://www.jpcert.or.jp/)などの公式情報も参照します。今回のテストは本番記事として公開せず、テスト完了後に専用ブランチから削除します。
