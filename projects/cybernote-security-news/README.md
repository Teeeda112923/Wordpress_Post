# CyberNote Security News

CyberNote向けの短いセキュリティニュース記事を管理する専用領域です。一般記事、AWS障害投稿、無関係なワークフローとは分離して運用します。

## 管理対象

- 候補: `data/news_candidates.csv`
- 管理簿: `data/news_ledger.csv`
- 記事: `articles/`
- アイキャッチ: `eyecatches/`
- 品質・投稿結果: `results/`
- 候補選択: `src/select_news.py`

## 投稿運用

定期実行はSEO回復期間中、08:30 JSTの1日1枠です。1日に公開するのは品質ゲートを通過した1記事だけで、`select_news.py`は公開予定日が当日の未投稿記事だけを選びます。

記事生成・公開は1回1件、1日最大1件です。前日以前の記事は自動で拾わず、必要な場合だけ対象日を指定して手動実行します。

## 記事仕様

記事先頭のYAMLフロントマターに、次を登録します。

- `answer`: 40〜60字、句点で終える
- `cve`: 関連するCVE・脆弱性ID
- `faq`: 質問と回答を2組以上
- `sources`: 開発元、公的機関など信頼できる一次情報URLを1件以上

CyberNote GEO Kitが`faq`から「よくある質問」、`sources`から「参考・出典」を生成します。そのため本文に`FAQ`、「よくある質問」、「参考情報」、「参考・出典」のH2は置きません。

本文は次の基準で作成します。

- 本文コアの絶対最低値は1,000字、目標は1,300〜1,600字、絶対上限は1,800字
- 冒頭リードは250〜300字
- まとめ以外のH2直下の説明は100〜150字
- 最後のH2は`## まとめ`を1件だけ置き、本文は250〜300字
- 序文直後のCocoon参照ブログカードは1個
- CyberNote内部リンクは3本以上
- 同一の内部リンクや同じ見出しを重複させない
- `結論`、`総括`、`最後に`、`この記事のまとめ`、`対応のまとめ`を別のH2として置かない
- 箇条書き・表の直前と直後はそれぞれ150字以上
- 未確認情報を断定しない

文字数は`geo_article_quality_check.py`の`chars()`と同じく、フロントマターを本文から分離し、空白、改行、Markdown記号、HTMLコメントを除いて数えます。1,000字未満と1,800字超はエラー、1,000〜1,299字と1,601〜1,800字は再校正を求める警告です。新規記事は警告のまま保存せず、1,300〜1,600字へ修正します。

保存前はワークフローと同じコマンドで検査します。エラーまたは文字数警告があれば、対象版、成立条件、影響、悪用状況、更新方法、確認手順、国内利用者への影響、未確認事項のうち不足する事実を一次情報から補い、重複表現を削って再校正します。再計測と検査を繰り返し、終了コード0、エラー0件、本文1,300〜1,600字になってから保存します。チェッカー自体は根拠のない文章を自動生成せず、生成工程が検査結果を使ってMarkdownを修正します。

## 管理簿

「指定KW」には主対象の製品名だけを登録します。CVE番号、「脆弱性」、「更新」、「RCE」などを連結しません。

記事と画像の保存・検証前に「生成済み」へ変更してはいけません。次を確認できた場合だけ、生成ステータスを「生成済み」、レビュー判定を「未確認」、公開停止を空欄にします。

- 記事の品質チェックが成功
- 記事ファイルと管理簿のファイル名が一致
- 画像のPNG署名、形式、1,200×800px、完全デコードが正常
- 画像ファイルと管理簿のファイル名が一致

## アイキャッチ仕様

- 1記事につき1枚
- PNG、1,200×800px、横長3:2
- Noto Sans JP
- ダークネイビーを基調に、青灰色とシアンまたは緑を使用
- 警告が主題の場合のみ赤を使用
- URL、架空ロゴ、長文、コラージュ、複数案の一覧は禁止

保存時はPNG署名を確認し、Pillowの`Image.open()`後に`Image.load()`まで実行します。GitHubへ反映した後もファイルを再取得し、同じ検査を行います。

## GitHub Actions

`.github/workflows/cybernote-security-news.yml`は次のJST時刻で動作します。

- 08:30
- 10:30
- 12:30
- 14:30
- 16:30
- 18:30
- 20:30
- 22:30

品質ゲートを通った当日記事をWordPressへ直接公開し、成功後に管理簿を「公開済み」へ更新します。Imunify360による遮断時だけ、設定された待機時間後に再実行します。

## 必要なGitHub Secrets

- `WP_BASE_URL`
- `WP_USERNAME`
- `WP_APP_PASSWORD`
- `WP_EXTRA_HEADERS`（必要な場合）
- `ACTIONS_PAT`（遮断後の自動再実行に必要）

記事や画像がない日、一次情報を確認できない日、品質ゲートに失敗した日は投稿しません。
