# CyberNote Security News

CyberNote向けの短いセキュリティニュース記事を管理する専用領域です。

既存の一般記事用の articles/、eyecatches/、制作管理表、WordPress Auto Post ワークフロー、AWS障害投稿ワークフローとは分離しています。

## このフォルダの目的

- 日中に収集したセキュリティニュース候補を記録する
- 話題性の高い候補を1日1件選ぶ
- 1,000字以内の短い記事とアイキャッチ画像を保存する
- 18:30 JSTにWordPressへ下書き登録する
- 19:00 JSTに、停止されていなければ下書きのステータスだけを公開へ変更する

記事本文の生成と画像生成は、CyberNoteのWork上で実施します。生成後は、この記事管理簿と同じNoを使って、次の場所へ保存してください。

- 本文: projects/cybernote-security-news/articles/
- アイキャッチ: projects/cybernote-security-news/eyecatches/
- 管理簿: projects/cybernote-security-news/data/news_ledger.csv
- ニュース候補: projects/cybernote-security-news/data/news_candidates.csv

## 記事仕様

- 本文は1,000字以内
- 目標は700〜950字
- 序文は240字以内
- 内容は速報の概要、影響、利用者が確認することに絞る
- 過度に掘り下げない
- 内部リンクを1本以上入れる
- 出典となる外部リンクを1本以上入れる
- 未確認情報は断定しない
- 事実、推測、今後の可能性を分けて書く
- H2は2〜3個程度に抑える
- 本文の最後に参考情報を置く

内部リンクは、CyberNote内の実在する記事へ通常のMarkdownリンクで記載します。存在しないURLを推測で作成しないでください。

## アイキャッチ仕様

- 1記事につき1枚
- PNG
- 1,200×800px
- 横長3:2
- ダークネイビー基調
- Noto Sans JPを使用
- 記事の主題を表すビジュアルを1つ配置
- 文字は少なく、大きく読みやすくする
- コラージュ、グリッド、複数案の一覧は禁止
- URL、架空のロゴ、記事本文の長文は入れない

## 管理簿のステータス

生成後は、最低限次の値を設定します。

- 生成ステータス: 生成済み
- レビュー判定: 未確認
- 公開停止: 空欄
- 公開予定日: 公開したい日付
- 記事ファイル: articles/配下のMarkdownファイル名
- 画像ファイル: eyecatches/配下のPNGファイル名

19:00の公開を止める場合は、GitHub Actionsの該当ワークフロー実行をキャンセルしてください。加えて、公開停止列に「停止」と記入してコミットしておけば、再実行時も公開されません。

18:30の下書き登録後にWordPress管理画面で本文を修正した場合、19:00の処理は本文を上書きせず、投稿ステータスだけを変更します。18:30の下書きを作り直すために再実行すると、下書き内容が管理簿とファイルの内容で更新されるため注意してください。

## GitHub Actions

ワークフローは次のUTC時刻で動作します。

- 09:30 UTC = 18:30 JST: 下書き登録
- 10:00 UTC = 19:00 JST: 公開

手動実行では、draftまたはpublishを選択できます。初回はdraft、dry-run、対象日を指定して確認してください。

このスケジュールは、変更をmainへマージした後に有効になります。既存のWordPress Auto PostやAWS障害投稿のワークフローは変更しません。

## 必要なGitHub Secrets

既存のWordPress投稿用Secretsを使用します。

- WP_BASE_URL
- WP_USERNAME
- WP_APP_PASSWORD

OPENAI_API_KEYはWorkで画像生成を行う場合に使います。WordPress投稿ワークフロー自体では使用しません。

## 生成前の確認

1. 公式発表または信頼できる一次情報を確認する
2. 発生日、製品名、影響範囲、対策を確認する
3. CyberNote内の重複記事を確認する
4. 管理簿に候補を記録する
5. 話題性の高い1件を選び、記事と画像を保存する
6. 文字数とリンクを確認する
7. 生成ステータスを生成済みにする
8. GitHubへコミットする

記事が用意されていない日や、情報の信頼性を確認できない日は投稿しません。
